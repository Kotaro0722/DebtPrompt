# テストケース一覧: `main_db.delete_DB`

## 対象関数

```python
def delete_DB(id):
    sql_delete_data=f"DELETE FROM {main_table} WHERE id={id};"
    my_update(sql_delete_data)
```

- 引数の `id` を条件にDELETE文を組み立て、`my_update` を1回呼び出すだけの関数
- 3関数中もっとも単純（引数は `id` のみ）

## MECEの切り口

分岐が無いため、結果は以下の2つで完全に分割できる。

- **A. 正常系**：`my_update` が正常に完了する
- **B. 異常系**：`my_update` が失敗し、例外が発生する

## テストケース表

| No | 分類 | ケース内容 | 入力例 | 期待される結果 | 対応するテスト | 状態 |
|----|------|-----------|--------|----------------|----------------|------|
| 1 | A. 正常系 | 基本的な `id` でDELETE文が正しく組み立てられる | `id=100` | `"DELETE FROM {main_table} WHERE id=100;"` を引数に `my_update` が1回呼ばれる | - | 未実装 |
| 2 | A. 正常系 | `id` がDiscordスノーフレーク相当の大きい整数でも正しく埋め込まれる | `id=123456789012345678` | SQLにその値がそのまま含まれる | - | 未実装 |
| 3 | B. 異常系 | `my_update` が失敗した場合、`delete_DB` は例外を握りつぶさず伝播する | `my_update` が例外を発生 | `delete_DB` の呼び出しが例外を発生させる | - | 未実装 |

## スコープ外

- 引数の妥当性チェックが無いため、`None` 等の不正な `id` による挙動は対象外
